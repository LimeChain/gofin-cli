# Kamino lending and farm protocol sources

Protocol identities, layouts and native instruction account order are independently validated against RPC account owners. Public API values are descriptive, not authority or settlement evidence.

- `kvault-interface = 0.1.0`, Apache-2.0, official Kamino-Finance/kvault commit `0426eb126570c5d2f4ab1de2fa2582cf5b1d6e20`, `libs/kvault-interface`. Used directly for vault/global configuration decoding, PDA derivations, native deposit and withdrawal account graphs.
- `klend-interface = 0.6.0`, Apache-2.0, official Kamino-Finance/klend commit `23b9f2b54530784ef1d9d0e08c5256e1eafe4a04`. Used directly for reserve and market decoding. Source/version/checksum are pinned by Cargo.lock.
- Official Kamino-Finance/klend-sdk (MIT license per package metadata) commit `3c3a38d4ff9d7cf7b0380a383b81c9cd4f0f58b8`: `src/@codegen/kvault/instructions/depositWithMinSharesOut.ts`, `src/@codegen/kvault/accounts/VaultState.ts`, and `src/classes/farm_utils.ts`. The published Rust crate predates two compatible extensions: deposit-with-minimum-shares uses the identical deposit account graph plus discriminator `[74,127,128,80,4,221,193,91]` and a second `u64` argument; the first 32 bytes of reserved `padding_3` hold the optional permissioning authority. Permissioned vaults are reported restricted and require separate signer support.
- Official Kamino-Finance/farms-sdk commit `98a42f25597eefe5a7f8a51a0bd59df4c46d0f7f`, Apache-2.0: `src/@codegen/farms/accounts/{farmState,userState}.ts`, `src/@codegen/farms/types/{tokenInfo,rewardInfo,timeUnit}.ts`, `src/@codegen/farms/instructions/{initializeUser,stake,unstake,withdrawUnstakedDeposits}.ts`, and `src/utils/utils.ts`. `farms.rs` implements the pinned fixed-size layouts, documented PDA seeds and instruction wire formats without a JavaScript runtime.

Native farm stake uses an exact number of newly minted shares, with the lending minimum-share instruction ensuring those shares were created by this deposit. It never uses the SDK's stake-all sentinel to move unrelated pre-existing wallet shares. Immediate withdrawals honor the farm's locking and cooldown semantics and never silently accept an early-exit penalty. Issued unclaimed farm rewards are reported separately from unrefreshed reward accrual.

Lending valuation uses integer scaled fractions (60 fractional bits) from each authenticated reserve's latest stored state, less pending fees. It is labeled by observation and last-refresh basis; simulation and finalized receipts, not this estimate, determine actual execution receipts. API catalog reads use `https://api.kamino.finance/kvaults/vaults`; inactive accounts are also scanned on-chain with bounded coverage.

Farm ownership uses the exact ratio of user scaled stake to the corresponding farm-wide scaled stake and backing token amount. Whole share atoms are rounded down; raw scaled stakes and exact sub-atom remainders remain in position/quote details. Native withdrawals convert only the approved whole-share amount to scaled stake, without an exit-all sentinel. Simulation rejects an operation whose expected whole-share entitlement decrease exceeds the reviewed native redemption.

Finalized farm entitlement requires one finalized farm/user account snapshot at or after the receipt slot, followed by finalized signature-index checks for both accounts. The receipt must be their newest mention, and the preceding mention must be no later than the approved snapshot. Signature indexes contain read-only mentions too: concurrent activity can therefore conservatively leave settlement pending. Later unguarded balances are never attributed to the transaction; recovery requires historical transaction-specific account evidence if intervening mentions make the guarded proof unavailable. Token-custody mint/burn deltas remain separate from exact owned entitlement changes.

Lock modes follow the pinned enum: `0=None`, `1=Continuous`, `2=WithExpiry`. The official `Farms.ts` lockup calculation states that continuous locking starts individually at each stake and uses the single `lastStakeTs` field. Native staking therefore rejects existing active or pending scaled custody for continuous farms, including fractional custody; first stakes remain supported. Additional staking also rejects a nonzero warmup period with existing pending-deposit scaled custody because the shared maturity timestamp restarts. The owned cloned-program check `scripts/verify-kamino-lending-validator.py --farm-lock-semantics` confirms both timestamp resets using unsigned simulation and explicitly synthetic account configuration. Ordinary reads and eligible withdrawals remain supported.


Direct KLend obligations use the same pinned `klend-interface = 0.6.0` for native V2 supply, collateral redemption, floating borrow and finite repayment, including metadata/obligation initialization and delegated farm-user initialization. Obligation and delegated farm PDAs, configured reserve custody, and actual mint identities are verified; example token labels are not authority. Legacy main-market reserves use custody addresses recorded in their authenticated reserve state rather than the deterministic custody seeds assumed by the convenience helpers. Low-level official V2 builders use those configured addresses only after validating token ownership by the market authority, mint/program identities, initialized state, delegate/close authority, and collateral-mint authority. All configured custody identities are pinned in candidate authority terms. Supported writes are group-zero vanilla obligations without fixed-term debt, active orders, referral state or ownership transfer. Configured farm stake is virtual reward accounting for the obligation, never separate owned collateral or debt.

Native operation quotes simulate the V2 action and then refresh the actual resulting reserve set and obligation through the program. This establishes projected risk from the native program instead of treating stale pre-action risk as current. Custom receipt, debt, fee and health limits are fresh pre-sign checks; ordinary KLend V2 instructions enforce native protocol limits and exact native amounts but do not encode those additional client limits. All-repay uses the finite approved maximum and requires a zero post-debt result. No swap or implicit withdrawal queue is included.

Native supply uses the finite approved liquidity maximum. The pinned program's `Reserve::compute_depositable_amount_and_minted_collateral` (`programs/klend/src/state/reserve.rs`) floors minted collateral and then ceils the liquidity required for those collateral units. Quotes disclose actual expected debit and retained liquidity. In addition to the original input cap and exact native graph, finalized validation checks the rounding bound `(maximum - actual_debit) * minted_collateral < actual_debit`; this follows directly from the native floor/ceil conversion and prevents accepting arbitrary partial supplies without relying on a later reserve exchange rate.

Direct lending principal uses exact collateral-token units for supply and underlying debt atoms for variable debt. Current underlying supply exposure is a separately observed, conservatively rounded reserve backing value. Final settlement authenticates obligation poststate with finalized signature history: the receipt must be its newest mention, with the preceding mention no later than the approved snapshot. Busy reserve account state is never substituted for transaction-time obligation evidence. Remaining debt entries carry a refreshed big-fraction index, permitting exact integer interest normalization; full repayment deletes that index, so exact whole-atom repayment and interest are proved from zero debt and native receipt cashflow while the final sub-atom fraction remains explicitly unknown.
