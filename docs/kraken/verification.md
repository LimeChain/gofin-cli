It verified original order/trade/ledger settlement, exact total fees of 0.040210 USDC, restart and duplicate invocation without replay, zero final open orders/positions and unchanged unrelated balances. The explicit 0.010429 USDC residual is below the venue minimum for conversion. Exact numerical restoration is not claimed; the report accounts for fees, execution-price movement and nonreturnable dust. The observed omission of optional cash credit fields, the large public catalog and native zero-leverage markers produced three narrow parser/transport fixes and focused regressions. This SOL/USDC run itself establishes no native Touch ID or protected isolation evidence.

On 13 October 2026, a separately authorized automatic-development named plan completed **3.5 USDC from Base → Kraken, a 0.0012 ETH FOK limit buy, and a 0.0011 ETH gross withdrawal back to Base**. The buy filled at 2,526.28 USDC/ETH with a 0.009095 USDC fee. The independent recipient received 0.00095 ETH after the 0.00015 ETH withdrawal fee; deposit gas was 0.000001243781447626 ETH. Restart during the pending withdrawal and duplicate logical requests retained the original submissions. All operations completed, reservations cleared and unused authority was revoked. Scenario residuals were 0.459369 USDC and 0.0001 ETH at Kraken; exact numerical restoration is not claimed.

The protected human retest on the same date completed **0.005 ETH on Ethereum → 12.652757 USDC, a 12.55 USDC Kraken deposit, a 0.0049 ETH FOK limit buy, and a 0.00488 ETH gross withdrawal back to Ethereum**. The buy filled at 2,528.21 USDC/ETH, costing 12.388229 USDC plus a 0.037165 USDC fee. The independently verified destination received 0.00474 ETH after the 0.00014 ETH withdrawal fee. Wallet aliases worked in human-facing input while the observer verified the exact network and address.

These are selected live Spot, funding and recipient-proof observations, not coverage of all endpoints, options, permissions, Futures, margin, Earn or administrative changes. ## Human onboarding and Touch ID checklist — partially observed

The selected protected financial plan and human update above are observed. Product enrollment variations, administrative approval, cancellation/expiry and broader isolation cases below still require their own evidence.

1. In the human's own terminal, install the completed build using the repository onboarding instructions. The protected retest above followed a human update; agents do not install production builds as part of automated verification.
2. Enroll separate Spot and Derivatives credentials privately with the correct nonsecret account identity. Confirm displayed venue-verified and human-verified relationships and actionable missing-permission errors. No credential appears in arguments, JSON or logs.
3. For an explicit default wallet ID, confirm authenticated ownership and the human-confirmed default relationship. Remove/re-add must preserve its durable alias relationship; conflicting retargeting must fail closed.
4. Read capabilities/schema and public/private observations without financial approval. Redirected and JSON output must contain no prompts, animation or color; a configuration request in JSON must return the human-terminal handoff.
5. Run a harmless selected administrative configuration only after reviewing its exact terminal summary. Observe fresh native Touch ID, cancellation and expiry behavior; a financial plan must not authorize that administrative change.
6. Separately authorize one bounded live acceptance scenario with chosen accounts, amounts/destinations, full initial financial state and complete restoration, within the shared $100 allocation including costs. Observe fresh production approval, exact submission identity, real venue settlement and required recipient/credit evidence. Reconcile unknown responses without replay.
7. Restore allocation, holdings/exposure, positions/debt and changed allowances net unavoidable costs. Observe fresh protected approval for cleanup. Do not mark acceptance complete while restoration remains unresolved.
