# Coinbase product contract

This directory pins the Coinbase surface to the three REST clients shipped in CCXT 4.5.85. The complete native endpoint declarations, inherited capability flags, explicit features and options are in [pinned-ccxt-4.5.85.json](pinned-ccxt-4.5.85.json). The [versioned native-to-GoFin matrix](contracts.json) links every implicit endpoint declaration to a GoFin operation, schema, authorization and implementation when one exists; unmapped endpoints are marked `inventory_only`, and deliberately narrow implementations are `partial`. The counts are 97 App/Advanced, 103 Exchange and 58 International declarations.

The matrix also records each pinned unified method, its emulation flag, native dependencies and linked GoFin operations. Dependency links are derived from the pinned Rust method calls; inherited helpers without proven endpoint links remain inventory-only. Streaming methods remain excluded. A method link does not establish support for every native option.

Native GET coverage also includes 166 active closed routes in [the compiled read inventory](../../crates/gofin-exchange/src/coinbase/reads.rs). Each route has a fixed product, path, named path identities and a closed query subset. Discovery exposes these under `<provider>.read-<version>-<access>-…`; each response is one page and pagination is explicit. Routes requiring options outside the current declared subset remain `partial_options` in the matrix. The removed App Show User and four retired retail INTX read routes are excluded from this executable inventory; the standalone International client remains separate.

The GoFin product profiles are `coinbase` (App v2 plus Advanced Trade v3), `coinbaseexchange` (institutional spot) and `coinbaseinternational` (spot, margin and perpetual products). Product, portfolio, currency-account, network and order identities remain separate. The API key's permitted portfolio is the effective Advanced Trade scope; the legacy `retail_portfolio_id` parameter does not establish an alternate scope.

Order creation accepts typed Advanced spot market IOC, SOR IOC, limit GTC/GTD/FOK and stop-limit GTC/GTD payloads. Reusable boundaries and named plans support single-order spot configurations with bounded size, cumulative quote fees and venue-enforced limit price ceiling/floor; scheduled end times and stop trigger controls remain fixed in authority. FOK provides a bounded-price path without treating a market order's post-fill minimum receipt as slippage protection. Market FOK is omitted because Coinbase documents it for derivatives rather than this spot scope. TWAP, scaled and trigger-bracket/attached orders remain unfinished until their child or aggregate financial effects have a finite reconciliation contract. Submissions reconcile exact persisted response bytes or product-scoped paginated order history matched to the original client ID, then authoritative order lookup and independently paginated fills; acceptance alone is not settlement. Single and batch cancellation verify exact open orders and link terminal proof to original submissions while preserving those operations as fill owners. Cash snapshots retain the configured portfolio identity and record each currency-account UUID as coverage. Feasibility reads product metadata and previews the exact immutable order body. Portfolio movement is supported only for Advanced portfolio-to-portfolio cash moves; a lost response without captured native receipt remains unknown, and source/destination deltas must both match exactly before a transfer effect is recorded. The CFM margin-mode configuration change requires separate human-interactive authority and successful native readback. CFM sweep operations remain disabled until source and destination settlement can be bounded and proven. Institutional order/report lifecycles remain narrowly scoped; additional funding, lending, derivatives and administration are unfinished. External funding without a pre-dispatch fee bound is unavailable.

## Product and lifecycle boundaries

Institutional spot orders also support finite sequential plans and cumulative size, price and quote-fee boundaries. Future-funded review may defer only a verified current cash shortfall; International preparation uses native instrument, spot fee-tier and portfolio data; the pinned client has no native order-preview endpoint. Runtime preparation and dispatch still require spendable funds and fresh native checks. Product namespaces remain separate in intents, effects, prices and snapshots. Mixed profiles compose observations across products without merging equal currency symbols or custody resources; debt, collateral or derivative exposure that is not fully modeled makes the snapshot incomplete.

Named-plan order attempts receive distinct broker-generated request identities before dispatch; retries after verified no-send failures cannot reuse a prior native client order ID. Advanced order creation refreshes permissions, preview and USD observations after cash reservation, preserving the approved request, limits and expiry. Final transport checks still reject expired authority or prices.

Pricing uses exact native App/Advanced, Exchange or International spot identities. USD is an explicit fiat unit where supported. USDC/USDT retain observed conversion rates rather than assumed parity. Fiat inverse pairs use a conservative native bid with separate native base/quote and conversion identities. International quotes retain the native timestamp and exclude perpetual or halted instruments.

The Advanced retail `/intx` perpetual trading product was retired on October 1, 2026. Coinbase identifies its Deribit-backed replacement as a separate JSON-RPC gateway; that gateway is absent from these pinned REST clients and outside this contract. This retirement notice does not establish retirement of the separate HMAC-authenticated International REST client. See Coinbase's [retirement notice](https://docs.cdp.coinbase.com/coinbase-app/advanced-trade-apis/guides/perpetual).

An HTTP success response is an observation or an accepted request. It is not proof of settlement. The protected execution flow must independently observe source debits, fills, fees and final transfer status. Advanced fill reconciliation refuses rows when Coinbase reports that EU SCA proof is required or supplies a malformed proof requirement. If a dispatch result is uncertain, the persisted identity must be reconciled; the action must not be replayed.

International portfolio creation, name updates, margin override, cross collateral and auto margin settings use separate human-interactive configuration authority. GoFin captures the current setting before approval, binds the enrolled portfolio and exact request, and requires a captured native response plus exact portfolio readback for completion. Creation requires the returned native portfolio identity. Portfolio deletion is absent from the pinned International route map. These configuration operations have synthetic evidence; International live writes remain unverified.

Local dispatch rejection produces a protected certificate bound to the exact prepared request and persisted submission. Only a validated certificate proves that no HTTP write was sent and allows reservation release and a deliberate retry. A transport timeout, lost response or empty history scan provides no such proof. Client order identities remain unique across durable submissions, including International edit successors; changing the CLI request ID cannot reuse an existing native order identity.

The [App changelog](https://docs.cdp.coinbase.com/coinbase-app/introduction/changelog) announces deprecation of select legacy Buys and Sells APIs in its October 23, 2023 entry. Legacy write lifecycles remain unimplemented; the notice alone does not prove removal of every declared route. Advanced Trade provides the implemented typed spot trading path.

## App USDC withdrawal on Base

`coinbase.withdraw` sends an exact recipient principal from a verified Coinbase App USDC currency account to an enrolled Base wallet. It requires `account`, `accountId`, `destination`, `address`, `network: "base"`, exact decimal `amount`, `feeMode: "venue_calculated"`, `feeReserveUsdc` and `requestId`. The wallet alias and full address must resolve to the same enrolled Base destination and native USDC contract. Arbitrary destinations, networks, token contracts and raw send parameters are unavailable.

Coinbase's [Send Crypto](https://docs.cdp.coinbase.com/coinbase-app/transfer-apis/send-crypto) contract publishes no pre-send fee quote or maximum-fee input. This operation therefore requires explicit approval of **Coinbase-calculated additional fees, without a guaranteed cap**. `feeReserveUsdc` is a finite up-front accounting/policy reservation, not a fee estimate or a fee cap. The typed `venue_calculated_additional_debit` cost treatment is included in the approved financial intent; ordinary cost treatments retain their existing hard caps. The full actual fee is booked from terminal venue evidence, including when it exceeds this reserve. Available balance checks establish funding at observation time, not a fee guarantee. GoFin reports actual costs and rolling usage afterward. Standalone exact approval and exact-input named plans support this fee mode. A named plan binds the same principal, source, destination and positive finite fee reserve, and its native approval explicitly discloses that Coinbase fees are not capped. A preceding verified sale can fund the principal through an explicit `principal_only` funding dependency. Fees are paid from the explicitly approved Coinbase account cash, which may include remaining sale proceeds; available cash must cover principal plus reserve before dispatch. `all_debits` dependencies are rejected for this fee mode because an uncapped fee cannot be guaranteed to fit finite producer proceeds. Settlement records the full actual fee, including any excess over the reserve, without creating further funding authority. Scoped runs, bounded plan variations and reusable boundaries remain unsupported.

Before dispatch, GoFin verifies transfer permission, the key-bound portfolio, exact App/Advanced currency-account relationship, usable USDC and the enrolled Base destination. It generates a UUIDv4 `idem` and freezes the exact request in the approval-bound prepared operation, persisting submission identity before sending. Reconciliation uses that original identity and captured receipt. Response loss or an incomplete history scan never permits automatic replay.

Completion requires terminal Coinbase source-debit and explicit fee evidence plus an independent canonical Base native-USDC receipt to the exact wallet. Missing fee evidence is not treated as zero; missing source or destination proof leaves the original submission unresolved. The [transaction resource](https://docs.cdp.coinbase.com/coinbase-app/track-apis/transactions) supplies the send's network hash and fee after submission. Optional `travelRuleData` supports the [documented Travel Rule fields](https://docs.cdp.coinbase.com/coinbase-app/transfer-apis/travel-rule) for the human's own self-hosted wallet: `beneficiary_wallet_type: "WALLET_TYPE_SELF_HOSTED"`, `is_self: "IS_SELF_TRUE"`, an explicit `beneficiary_name`, and `beneficiary_address: {"country": "BG"}` (using the actual beneficiary country). The object and nested address are closed; unknown fields, third-party/exchange wallet modes and control characters in names are rejected. GoFin binds these values into approval and the exact native `travel_rule_data` body without inferring a legal name or residence. A captured native rejection for missing fields is reconciled before a deliberately corrected request. Other regional or account requirements remain explicit venue restrictions. Synthetic tests and any private live execution evidence establish only the scenarios actually observed; no native Touch ID or live-withdrawal claim follows from discovery alone.

## Authentication and supported order configurations

The transport accepts only explicit CDP Ed25519 or ECDSA keys, Exchange HMAC, or International HMAC. Credentials are injected through a protected API object and are absent from profile schemas. Advanced order payloads are endpoint-specific DTOs. Current Coinbase order documentation also describes bracket, attached, TWAP and scaled configurations; these need finite typed variants before they can be advertised as supported. The create-order schema marks legacy `retail_portfolio_id` deprecated and limited to legacy keys, so it cannot override the key-bound portfolio. See [create order](https://docs.cdp.coinbase.com/api-reference/advanced-trade-api/rest-api/orders/create-order) and [order management](https://docs.cdp.coinbase.com/coinbase-app/advanced-trade-apis/guides/orders).

Base deposit fixtures model a correlated receive hash, but Coinbase's archived transaction schema only guarantees `network.hash` for sends. Native receive correlation remains unverified. GoFin leaves the deposit pending when the exact source hash is absent; matching address, amount or balance alone cannot substitute for it. Synthetic deposit tests do not establish a usable live funding route.

Exchange profile discovery, creation and rename use `coinbaseexchange.get-profiles`, `create-profile` and `rename-profile`. Writes require separate configuration authority and exact native identity/readback; creating a profile does not enroll it for financial execution. Profile deactivation remains unavailable because its native route transfers all funds without an atomic zero-balance condition or bounded transfer receipt.

A negative Advanced conversion status alone does not prove zero financial effects. Failed, rejected or expired conversions without conclusive ledger evidence remain unknown, retaining reservations and the original submission identity.
